## Findings

### Internet/access changed

- Large parts of the historic suite now hit access protection or non-content pages. Representative hosts include ScienceDirect, ACM, BioRxiv, Wiley, The Lancet, WorldCat, JSTOR, Taylor & Francis, APA, Ash, DeGruyter/DeGruyter-Brill, IOP/Radware, BMJ, Cell/OUP, Karger, and LibraryThing.
- Several institutional/catalog URLs are dead or migrated: Hebis object URLs, KIT Primo end-of-service pages, old Citeseer/Copac URLs, old AIFB/OpenRepository/DSpace records, and various 404/503 cases.
- These should mostly be replaced by DOI/search-based cases or retired from the Zotero hard gate. Rebuilding bypass logic would reproduce the maintenance burden this migration is trying to remove.

### Fixable Zotero/client issues

- The Java wrapper currently tries `/web` first whenever a URL is present. For selected DOI/ISBN/arXiv/PMID input paired with a generic URL, this can scrape the generic page and never try `/search`. Later fix: prefer selected identifiers over generic URL scraping.
- Zotero HTTP `500` often wraps upstream fetch/access errors. Later fix: treat translation-server `500` as no-result/fallback, then try identifier extraction/search where possible, and log the original server error.
- PDF URLs often fail while canonical landing pages work. Example family: ACL Anthology PDFs should be normalized to landing pages before or after a failed `/web` request.
- Some failed URL cases contain a DOI that direct Zotero `/search` can recover. Subagent spot checks found recoverable examples among IOP, APA, IEEE Computer Society, Mendeley, NASA ADS, Springer, and Thieme cases.
- Some Zotero exports put DOI-like values in `url` instead of `doi`. Later comparator/postprocessing can decide whether to promote `http(s)://doi.org/...` URLs into DOI fields.
- Add quality filtering for obvious bot/security-page titles so BibSonomy does not accept `Just a moment...`, `Security Check`, or similar pages as publications.

### Old fixture/test-suite issues

- Some old fixtures are stale or encode old scraper behavior rather than authoritative metadata. Examples from spot checks: AAAI ICWSM expected `2021` while current page metadata points to `2011`; Amazon product URLs now expose different product metadata; PubMedCentral and Project MUSE dates differ from current pages.
- Some failures are comparator policy rather than scraper defects: TeX/encoding normalization, contributor initials vs family-name matching, date strings in `year`, ISBN-10/ISBN-13/eISBN equivalence, and DOI present via URL.
- Generic `BibtexScraper`, `COinS`, and `DublinCore` tests are useful import-format coverage, but they are not direct Zotero URL-scraping parity tests. Keep them out of the Zotero hard gate unless rewritten as publication URL/identifier cases.
- arXiv date behavior needs a product decision. For `cond-mat/0508028`, the old fixture asserts preprint-era year while Zotero appears to prefer published/final metadata.

## Recommended Next Fix Order

1. Wrapper behavior: prefer selected identifiers; soften translation-server `500` into no-result plus identifier fallback.
2. URL normalization: PDF-to-landing-page for known hosts, DOI URL extraction, and stricter DOI extraction from arbitrary URLs.
3. Quality filters: reject obvious bot/security/challenge pages instead of accepting them as publication metadata.
4. Comparator/test policy: normalize ISBN-10/13 and contributor/date/TeX edge cases without weakening DOI/title checks globally.
5. Case-list cleanup: retire or replace protected/dead/migrated URLs; keep valid Zotero-parity cases as hard gates and track unresolved Zotero gaps separately.
